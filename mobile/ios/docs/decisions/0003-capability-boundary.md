# ADR 0003 — Native capability boundary (proposal)

The validated baseline is ios/main 3b209e9121b64edacfce8cca3f58930af1efccff, CI run 45932697497: 16 portable, 3 Rust host and 6 hosted simulator tests passed, both ARM64 builds and artifact upload succeeded. Device validation #4 remains open.

Use the actual, unchanged upstream rust/crates/openjarvis-security/src/capabilities.rs from pin 556ddf32456bdf5c40195714a3385b339b5f98f9 (Git blob f42a68827c969138f0a494960564df90eaf78435). Its full parent crate also depends on the engine, network stack and bundled SQLite; those are deliberately not introduced here. A Rust path module compiles the upstream source directly inside the existing bridge; the build script verifies the exact blob. Building from a full Git checkout is required. The only new direct dependency is serde with derive, already present in the locked graph. Cargo --locked must verify this root-edge-only lockfile change.

Policy is constructed from trusted constants, default deny, agent identity and resource are fixed locally, and only reply, current_time, search_memory and save_memory are eligible. No dynamic grants, generic resource strings, network, file, shell, scheduling or admin access. JSON string ABI prevents embedded NUL from becoming an authorized truncated action; malformed/oversized input and panic return deny. The Swift allowlist is an independent mandatory check; the native app injects NativeToolAuthorization. Approval is separate from capability eligibility and is checked again after restart; implicit context retrieval requires memory read capability. Historical messages remain part of conversation context; memory-read gating is not a redaction guarantee. Direct user-initiated erase/delete remains available. No claims of injection scanning, comprehensive security, secure storage, or full upstream runtime migration.

New tests are authored: five portable, two bridge-specific Rust tests plus the upstream module's five original tests, and two native simulator tests; existing native approval tests now use actual native policy. Actual counts and outcomes must be verified in CI. This is a scoped proposal pending checks and physical baseline validation.
