# ADR 0006 — SQLite archive persistence (foundation)

Baseline ea42e1811513fc892bbb2550e70ca1efa9cd2a6b; PR #16 merged, run 45937808941 portable 38 tests passed; native still executing at initial observation. Prior fully validated run 45936370068: 49 total tests, artifact 15171057055.

Use OS SQLite through a SwiftPM CSQLite system library target (no external Swift or Rust package). Linux requires libsqlite3-dev and pkg-config; iOS builds must validate Apple SDK headers and linking. This is a mobile-specific persistence foundation, not the original upstream SessionStore. Keep existing JSON session repository and app wiring unchanged.

Version 1 stores ordered session IDs, titles, Foundation reference-date timestamps, exact Agent Snapshot bytes and active selection in two relational tables. Import validates unique IDs, title, selection and decodable snapshots, uses bound SQL parameters, foreign keys, BEGIN IMMEDIATE, rollback journal and FULL synchronous mode. Read back exact archive within transaction before commit. Duplicate imports refuse overwrite; unknown versions, unrelated unversioned schemas, inconsistent rows and invalid snapshots fail rather than reset. Connection lifetime is owned by a private wrapper. Tested with synthetic archives only. No live JSON migration or production database is opened by this change; no deletion of source files. No FTS, vectors, embeddings, encryption or query performance claim. Full snapshots remain blobs; message-level indexing and CRUD will be separate.

Local Linux Swift 6.2.1 and SQLite 3.46.1: swift test on the earlier v0.2 portable source fixture with exact new Package.swift, CSQLite module and store/test files: 23 passed (16 existing plus 7 new). Tests verify exact roundtrip/reopen including pending approval, rejection without writes, duplicate import, rollback when second insert fails, unknown version/unrelated DB, invalid persisted snapshot and closed handle.
