# Native artifacts and versioned unsigned IPA releases

The mobile CI packages unsigned ARM64 device and simulator app bundles plus a development IPA after portable tests, the reusable repository security audit, Rust bridge tests/cross-build, Xcode compilation for both platforms, and hosted native simulator tests succeed. Bundle identifiers, executable names, Mach-O platform markers, IPA `Payload/` layout and archive integrity are checked. A manifest and SHA256SUMS record the source commit, run, Xcode, Cargo lockfile hash, file sizes and digests. Build artifacts do not establish physical-device execution.

For a release candidate, push a valid `ios-vX.Y.Z` tag that points to a commit contained in `ios/main`. The same complete CI workflow runs. It injects the tag version and CI run number into the Xcode build, verifies the resulting app version, creates `OpenJarvisMobile-ios-vX.Y.Z-unsigned.ipa` with the conventional `Payload/` layout, checks archive integrity and confirms no provisioning profile or code signature was packaged. Publication occurs only after all validation jobs pass. The IPA, manifest and checksum file are uploaded as a versioned GitHub Actions artifact and retained for 90 days.

The IPA is unsigned and is not directly installable. It contains no signing identity or provisioning profile; a developer must re-sign it with a local Apple development team before installing. Tagging does not create a GitHub release, App Store submission or production distribution. Physical-device signing, installation, file-protection behavior, model availability and runtime acceptance remain tracked separately in issue #4.
