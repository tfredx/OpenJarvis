# Personal briefing validation

Baseline `76acd8ddb8ae977d501315fe3efd1b5d45ca0ddb` includes the scoped Calendar reader from PR #31. This increment uses the native capability dispatcher and adds the Reminders read and write adapters. The app does not register these adapters or request OS permission yet.

The runner accepts a user-selected UTC interval, retrieves Calendar events and incomplete reminders in sequence, and analyzes overlaps and truncation locally. The result includes bounded event and reminder summaries. Creation is a separate operation for a typed user draft. The installed approval surface must display the exact title, due time and trusted destination list. Candidate tool outputs remain data. They never initiate a write.

The dispatcher checks cancellation, independent application authorization and human approval before calling the adapter. The Reminders adapter requires existing full EventKit access and explicit list IDs, uses a bounded read window, checks revocation before returning results, and checks the destination list is writable before creation. The [EventKit authorization documentation](https://developer.apple.com/documentation/eventkit/accessing-the-event-store) describes full access for Reminders. Permission activation requires an explicit scope review and user authorization. Read cancellation suppresses delivery when EventKit returns. Immediate cancellation of an in-flight OS fetch is outside this implementation.

The runner claims a write checkpoint after approval and before dispatch. A successful provider result closes the checkpoint. A thrown provider error, interruption or malformed checkpoint leaves the outcome uncertain. Use the same task ID on reopen and present reconciliation to the user. The checkpoint contains one state byte. The host must retain the stable task ID and provide a protected, backup-excluded app-owned directory. This is a process-interruption safeguard, with no power-loss guarantee or global duplicate matching across distinct task IDs. Broader durable task storage and SQLite activation are later increments.

Scripted tests cover action ordering, overlap analysis, independent approvals, denial, successful completion and uncertain outcomes on reopen. Run the full portable and native CI before integration. On device, use synthetic selected and excluded lists, deny and revoke authorization, review the write preview, verify the committed reminder in Reminders, and interrupt after the checkpoint to confirm no replay.
